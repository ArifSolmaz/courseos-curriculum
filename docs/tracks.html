Choose your track wisely

You'll live with this choice for 2 years. Every track uses the same contract and grading — but the domain, the data, and the final product are different. Read all five before deciding.

🤖

Robotics / Mechatronics

MechaSense Studio
You build a sensor monitoring and fault detection tool. It reads IMU, temperature, RPM, and vibration streams, cleans noisy data, detects anomalies and threshold crossings, and generates engineering reports with annotated time-series plots.
What you build (4 courses)
  • ✓ Multi-sensor CSV loader
  • ✓ Threshold + spike fault detector
  • ✓ Event counter (crossings, peaks)
  • ✓ Moving-average smoother
  • ✓ Time-series + distribution plots
  • ✓ JSON fault report with per-sensor stats
  • ✓ OOP: EventAnalyzer, RuleCleaner, CSVDataSource
  • ✓ DSA: sorted event index + binary search range queries
End product after 2 years

A command-line tool that takes raw sensor CSVs, validates and cleans them, detects threshold crossings and anomalies, generates labeled time-series plots with fault annotations, and exports a structured JSON report. Optimized to handle 100K+ readings with sub-millisecond range queries via binary search.

Sample output

"3 overtemp events in RPM sensor between t=120–180s, peak 94.2°C. 2 vibration spikes above 55g at t=45s and t=162s. Overall health: WARNING."

Trade-offs
  • ✗ Data is numeric and repetitive — less variety
  • ✗ Harder to demo visually to non-engineers
  • ✗ Can feel dry if hardware doesn't excite you
Best for: students who love hardware, sensors, and control systems. Directly relevant to your Mechatronics degree.

Data / AI

CleanReport Pipeline
You build an automated data cleaning and reporting pipeline. It takes messy CSVs with missing values, bad types, and outliers — validates them against a schema, drops bad rows with documented reasons, computes group summaries, and generates reports with dashboards.
What you build (4 courses)
  • ✓ Schema validator with clear error messages
  • ✓ Configurable cleaning rules (via config dict)
  • ✓ Group-by summaries and dict analytics
  • ✓ Outlier detector (IQR method)
  • ✓ Histogram + box plot + scatter dashboards
  • ✓ JSON + Markdown auto-generated reports
  • ✓ OOP: pluggable cleaners, analyzers (Strategy pattern)
  • ✓ DSA: hash-based aggregation + caching
End product after 2 years

A tool that takes any dirty CSV, checks it against a schema, drops invalid rows with per-reason counts, computes group statistics, generates labeled plots, and writes a complete report — JSON for machines, Markdown for humans. Cached aggregation makes re-runs near-instant on large files.

Sample output

"1,247 of 1,500 rows valid. Dropped: 142 missing, 89 out-of-range, 22 duplicate. Mean score by city: Cairo=78.3, Alex=82.1, Luxor=74.6."

Trade-offs
  • ✗ Doesn't showcase your Mechatronics identity
  • ✗ Can feel generic compared to robotics or space
  • ✗ Many students pick this — less distinctive
Best for: students who want the most transferable, career-safe skill. Every industry needs data cleaning.

Simulation / Games

SimLab Engine
You build a discrete simulation engine. It runs timestep-based scenarios, logs state at every step, computes scores, validates parameters, and generates trajectory plots and comparison reports. You design the rules.
What you build (4 courses)
  • ✓ Timestep loop with position, velocity, score
  • ✓ Parameter validation + boundary handling
  • ✓ Batch scenario runner (config-driven)
  • ✓ Deterministic seeded runs for reproducibility
  • ✓ Trajectory, score, and comparison plots
  • ✓ Scenario comparison reports
  • ✓ OOP: Simulator, Scenario, Logger, Reporter
  • ✓ DSA: spatial hashing / grid indexing for collision
End product after 2 years

A tool that takes scenario parameters, runs a simulation with your custom rules, logs every timestep, validates results against expected bounds, plots trajectories, and compares multiple runs side by side. Spatial hashing enables fast proximity/collision queries at scale.

Sample output

"Scenario A: 500 steps, final score 2,340, 3 collisions detected. Scenario B: 500 steps, score 1,890, 0 collisions. B is 23% safer with 19% lower score."

Trade-offs
  • ✗ Hardest to keep deterministic — randomness is painful to debug
  • ✗ Scope creep risk — easy to over-design the simulation
  • ✗ Less "real data" experience than other tracks
Best for: students who love designing systems, game logic, and creative rule-based problems. Most fun to demo.

Space / Astro

Lightcurve Explorer
You build a lightcurve analysis tool. It processes star brightness (flux) measurements, cleans noise and NaN values, detects flux dips that could indicate planet transits, applies detrending, and generates discovery reports with annotated plots.
What you build (4 courses)
  • ✓ Time-flux data loader (TESS-like format)
  • ✓ NaN/outlier cleaner for flux data
  • ✓ Threshold-based dip/transit detector
  • ✓ Configurable detrending algorithms
  • ✓ Lightcurve plots with dip annotations
  • ✓ Sector-by-sector summary reports
  • ✓ OOP: pluggable detrenders (Strategy pattern)
  • ✓ DSA: prefix sums for O(1) windowed statistics
End product after 2 years

A tool that takes raw star brightness data, cleans it, removes instrument noise via detrending, scans for significant flux dips, marks candidate transit events, and produces annotated lightcurve plots with a structured JSON report. Prefix-sum optimization enables instant windowed statistics over millions of data points.

Sample output

"Star TIC-29837: 2 dips detected at t=45.2d (depth 0.8%) and t=91.7d (depth 0.9%). Estimated period: ~46.5 days. Confidence: moderate."

Trade-offs
  • ✗ Need to learn basic astro concepts (flux, transit, sector)
  • ✗ Less directly tied to Mechatronics career paths
  • ✗ Fewer peers in this track — less help from classmates
Best for: students who want something unique and impressive. The "wow" track — instant conversation starter in interviews.

IoT / Reporting

AutoDashboard Reporter
You build a universal dashboard generator. Give it any time-series CSV — temperature, humidity, pressure, whatever — and it auto-maps columns, applies a dashboard profile, cleans the data, and produces a standard report. New device? Just change config.
What you build (4 courses)
  • ✓ Auto-detecting column mapper (aliases)
  • ✓ Standard IoT cleaning pipeline
  • ✓ Dashboard profile system (configurable layouts)
  • ✓ Multi-device batch processing
  • ✓ Time-series + summary dashboard plots
  • ✓ Per-device JSON + Markdown reports
  • ✓ OOP: plugin dashboard architecture
  • ✓ DSA: cached computation for batch speed
End product after 2 years

A tool that takes any IoT CSV, figures out the columns from aliases in config, cleans the data, generates a standardized dashboard with time-series and summary plots, and exports reports. Works with new devices without code changes. Cached computations make batch re-processing near-instant.

Sample output

"Device D01: 720 readings over 30 days. Temp range 18.2–26.4°C, 3 anomalies flagged. Humidity stable at 44–48%. Dashboard: 4 plots exported."

Trade-offs
  • ✗ Less specialized — generalist, not deep in one domain
  • ✗ Dashboard work can feel repetitive across weeks
  • ✗ Less algorithmic depth than robotics or space
Best for: students who want the most practical, industry-ready tool. Closest to real monitoring platforms (Grafana, Datadog).
