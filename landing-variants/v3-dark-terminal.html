COURSEOS(1) — Manual Page

How It Works

CourseOS is a project-based curriculum where every student builds the same type of product — a data pipeline — across four consecutive courses. You pick a track (domain), and your pipeline evolves from a simple Python script into a fully architected, algorithmically optimized system. Each course rebuilds the pipeline using the new skills you learn that semester.

Year 1 — Foundations

Fall (CP1): You start from zero. No prior programming experience required. By week 14 you ship v1 — a working pipeline written in pure Python scripts. It reads data, cleans it, and prints a summary.

Spring (CP2): You add real tools. Dictionaries for config, Matplotlib for charts, NumPy for speed, pytest for confidence. By week 14 you ship v2 — a packaged, tested, data-science-grade pipeline.

Year 2 — Mastery

Fall (OOP): You redesign everything with classes, patterns, and plugin architecture. By week 14 you demo v3 — a system anyone could extend without touching the core.

Spring (DSA): You profile your v3 and swap in proper algorithms. Hashing for lookups, heaps for priority queues, graphs for dependencies. The final report proves your pipeline is fast and correct.

A Typical Week

  • Colab notebook — guided walkthrough of the week's concept (done before class or during lab)
  • Homework notebook — apply the concept directly to your track's pipeline
  • Check notebook — automated self-grading; run it to see if you pass
  • Estimated time: 4-6 hours per week (lab + homework + reading)

Falling Behind & Recovery

Life happens. If you miss a week, the next week's Colab always starts with a recap. The check notebooks tell you exactly where you stand. You can catch up at your own pace — the system is designed so each week builds on the last but doesn't require perfection. The 80% completion threshold (not 100%) gives you breathing room.

Track Switching

You can switch tracks between courses (e.g., start with CleanSweep in CP1, switch to GameStats in CP2). The pipeline structure is identical across tracks — only the data domain changes. Switching mid-course is not recommended but possible with instructor approval.

Grading

Grading is effort-based, not perfection-based. Each week earns an effort score:

  • INCOMPLETE (0) — nothing submitted
  • ATTEMPTED (1) — ran but errors remain
  • COMPLETE (2) — all checks pass
  • POLISHED (3) — clean, documented, tested beyond requirements

Your course grade maps to the fraction of weeks at COMPLETE or above. >= 80% earns full credit. The contract's can_advance() method is not a metaphor — it's real code that runs on your repo.

AI Policy

AI tools (ChatGPT, Copilot, Claude, etc.) are allowed and encouraged — with one rule: you must understand every line you submit. The check notebooks include conceptual questions that AI cannot answer for you if you don't understand the code. We treat AI like a calculator in a math class: use it, but know what it's doing.
