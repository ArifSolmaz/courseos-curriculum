The Contract

Every track implements these 6 function signatures. Your product must honour this interface.

def load_raw(path: str) -> list[dict]:
    """Read raw data from file and return list of records."""

def clean(raw: list[dict], config: dict) -> list[dict]:
    """Validate and clean records according to config rules."""

def analyze(clean_data: list[dict]) -> dict:
    """Compute summary statistics and return analysis dict."""

def visualize(analysis: dict, output_path: str) -> None:
    """Generate and save charts from analysis results."""

def report(analysis: dict, output_path: str) -> None:
    """Produce a human-readable report file."""

def optimize(data: list[dict], strategy: str) -> list[dict]:
    """Apply DSA-backed optimization to the data pipeline."""

The Journey

Everything you need to know about how CourseOS works.

How It Works

You pick a track in Week 1 of CP1. That track gives you a domain, a dataset, and a product name. Over four semesters you build, refine, and optimize that product. Each course adds a new layer of skill. By graduation you have a portfolio-ready, fully tested, documented software project.

Year 1 — Foundations

  • CP1 (Fall): Learn Python from zero. Write scripts, loops, functions. Ship v1 — a working script that loads and processes your track's data.
  • CP2 (Spring): Add data quality, validation, visualization, testing. Ship v2 — a robust data pipeline with charts and reports.

Year 2 — Mastery

  • OOP (Fall): Refactor into classes, apply SOLID and design patterns, add plugins. Ship v3 — a modular, extensible architecture.
  • DSA (Spring): Benchmark, profile, apply algorithms. Ship v3+ — an optimized product with Big-O analysis and a final performance report.

What If You Fall Behind?

CourseOS uses Recovery Tickets. If you miss a deadline:

  • You get 3 recovery tickets per semester (no questions asked).
  • Each ticket extends one deadline by 7 days.
  • You can stack up to 2 tickets on a single assignment (14 days max).
  • Unused tickets convert to bonus points at the end of the semester.
  • If you run out of tickets, talk to the instructor — there is always a path forward.

Track Switching

You may switch tracks once, and only between CP1 and CP2 (i.e., during the break between semesters). After CP2 starts, your track is locked. Switching requires redoing any track-specific notebooks from CP1 that differ. Most of the work carries over because the contract functions are the same.

AI Policy

AI tools (ChatGPT, Copilot, Claude, etc.) are allowed and encouraged as learning accelerators. The rules:

  • Always cite: Add a comment # AI-assisted on any AI-generated line.
  • Understand everything: You must be able to explain every line of your code in a live check.
  • No copy-paste submissions: Running a prompt and submitting raw output is academic dishonesty.
  • Checks are oral: Weekly check notebooks include questions you answer live.
  • The goal is to use AI the way a professional developer does — as a tool, not a crutch.
